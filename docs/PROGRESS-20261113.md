## 2026-11-13 · 蓝牙上电链路打通，SE5 UART 端到端验证

这份接 `popsicle-port/STATUS-20261113-蓝牙上电链路打通与驱动审计修复.md`。
那边记的是驱动侧怎么改，这边记的是**这轮把哪些"未知"变成了"读数"**，以及三个
「我以为是硬件，其实是我自己」的错误。

一句话：**电源与时钟链已经全部打通，SE5 的 UART 自环 `a5 5a 3c c3` 四字节全对；
剩下的是芯片在 ROM 里对 EDL 一字节不回，以及长帧触发 `M_TX_FIFO_RD_ERR`。**

## 一、`C1A_E0`：第 8 个 RPMh 资源

Android `clk_summary` 里这一行是关键：

```
c1a_e0    0 0 0  76800000  0 0 50000  Y   b0000000.qcom,cnss-peach  rf_clk
                                        soc:bt_peach               bt_rf_clk1
```

`hardware enable = Y`、76.8 MHz、`enable_count 0` —— 由 RPMh 硬件常开，
所以从来不进 `btpower.ko` 的九路 `qcom,bt-vdd-*` 名单。来源链：

```
popsicle_overlay.dts  bt_peach { clock-names = "bt_rf_clk1"; clocks = <&rpmhcc 6>; }
        ↓  __fixups__: rpmhcc = ".../rsc@18900000/drv@2/clock-controller"
canoe_base.dts:5855   compatible = "qcom,canoe-rpmh-clk"; #clock-cells = <1>
        ↓
clk-rpmh.c            DEFINE_CLK_RPMH_VRM(clk1, _a1_e0, "C1A_E0", 1)
```

时钟投票与电压投票不同：**它是单命令 `{addr = address + 4, data = 1}`**，
不是电压的三命令 `{mv, 7, 1}`（`CLK_RPMH_VRM_EN_OFFSET 4`、`res_on_val 1`）。
cmd-db 里 `C1A_E0` 的地址是 `0x46000`，slave 4，但不满足电压路径的
`(addr >> 16) == 4` 判据 —— 所以 `rh_lookup()` 必须放宽这一条，否则查不到。

**实测效果**：

```
投票前  pad watch … pin24 high anytime 1 | pin27 low 100 high 0     ← TX 静态低
投票后  pad watch … pin24 high anytime 0 | pin27 low 0  high 100    ← TX 空闲高
```

芯片之前因为缺 RF 参考时钟停在 ROM 里；一投票它立刻把 TX pad 驱到 UART 空闲电平。

### 但「pin27 高电平」不是可靠判据

16 次 boot 里只有两次读到高，**重跑同一镜像仍然是低**。Android 侧反证：

```
/sys/kernel/debug/gpio        gpio27 : in high func0 2mA no pull
/sys/kernel/debug/pinctrl/…/pinmux-pins
                              pin 27 … function gpio
```

Android 自己也不把 pin27 挂 `qup3_se5_l3`，而它的 HCI 工作正常 ⇒ 在 func2 下读
TLMM IO 的 in 位**不反映焊盘电平**。判据已改用 `SE_GENI_IOS` 的 `RX_DATA_IN`(bit0)。

## 二、七路电压：DTS 的 `init` 不等于芯片实际跑的电压

`/sys/kernel/debug/regulator/regulator_summary`（BT OFF 与 ON 两次快照完全相同）：

| 轨 | Android 实测 | DTS `init` |
|---|---|---|
| `pmh0104_s2` (S2J_E1) | **892 mV** | 852 |
| `pmh0110_f_s7` (S7F_E0) | **1224 mV**（窗口最小值） | 1256 |
| `pmh0110_f_s8` (S8F_E0) | **1800 mV**（窗口最小值） | 1857 |
| `pmh0104_s1` (S1J_E1) | **892 mV** | 852 |

`pmh0110_g_l2/l3`、`pmr735d_l6` 三路实测与 DTS 相同（1800 / 1200 / 1700）。
892 mV = `0xd9c60`，正好是 `qcom,bt-vdd-{dig,aon,rfa0p75}-config` 的窗口下界。
教训：**DTS 的 `regulator-init-microvolt` 是驱动初始化用的起点，不是运行态读数。**

## 三、`sw_ctrl`：Android 其实是驱到 1 的

上游 `hci_qca.c` 只 `gpiod_get_value_cansleep(sw_ctrl)`（读），所以我按它删掉了对
TLMM 18 的驱动 —— 这是错的。Android 自己的 `dmesg` 写得很清楚：

```
BTON:Turn Bt OFF bt-sw-ctrl-gpio(530) value(1)
BTON: Turn BT ON bt-sw-ctrl-gpio(530) value(1)
```

`/sys/kernel/debug/gpio` 首行 `gpiochip0: GPIOs 512-729, parent: platform/f000000.pinctrl`
⇒ 530 = TLMM pin 18。现在按 Android 驱到 1。

## 四、SE5 UART：三个真缺陷，修完自环才 PASS

1. **RX 整字被 Linux 公式截成 1 字节。**
   `handle_rx_fifo()` 的 `total = 4*(words-1) + (partial ? lbv : 4)`，在这颗块上
   `words=1, lbv=1` 算成 **1**，于是每个 4 字节整字只取首字节。
   证据：`rx drain#1 st 0x90000001 words 1 last 1 lbv 1` → `rx word[0] = 0xc33c5aa5`
   （正是发出去的 `a5 5a 3c c3`，小端）。改成 `avail = 4 * words`。
2. **RX 序列器报 `RX_LAST` 后自己停，无人重启。** 环回拿到 1 字节后 2000 次轮询全空。
   新增 `bt_rx_restart()`（先等 `S_GENI_CMD_ACTIVE` 清，再 RMW `S_CMD0`）。
3. **`bt_gpio()` 的 `out ? 2u : 0u`。** `-1` 在 C 里是真值，所有输入脚被写成"驱动高"。

修完：

```
loopback: sent 4 B, got 8 B: fe 03 00 00 a5 5a 3c c3
       -> PASS: all 4 bytes came back (pattern at offset 4)
```

（前 4 字节是打开回环时块自己吐的一个 `0x3fe` 残留字，flush 冲在写之前冲不掉，
所以改成在窗口里搜 pattern。）

## 五、剩下的：ROM 静默 + `M_TX_FIFO_RD_ERR`

### 5.1 EDL 的编码我一开始就写错了

旧代码 `uint16_t op = BT_EDL_PATCH_OPCODE | BT_EDL_VER_REQ;` ⇒ `0xFC19`。
`btqca.c` 六处用法全是同一形态：**opcode 恒 `0xFC00`，子命令在参数第 1 字节**，
即 `qca_read_soc_version()` 的 `cmd = EDL_PATCH_VER_REQ_CMD(0x19)` 传进
`__hci_cmd_sync_ev(hdev, EDL_PATCH_CMD_OPCODE, EDL_PATCH_CMD_LEN, &cmd, …)`。
正确帧是 `00 FC 01 19`。**boot-xy 的 `vendor 0xfc19 -> 0 bytes` 是我发了芯片不认识的
opcode，那次结论作废。**

改对之后（`boot-yq`）：

```
vendor 0xfc00/0x19 -> -60 bytes (the ROM console is silent)
```

`-60` = `-ETIMEDOUT`。**ROM 确实静默**，与 `qca_setup()` 的顺序吻合 ——
固件下载排在通用 HCI 之前（`qca_power_on → qca_read_soc_version → qca_uart_setup →
qca_download_firmware`），所以 `0x1001` 要等 patch 跑起来才有人接。

### 5.2 `M_TX_FIFO_RD_ERR`（bit 28）

`m_irq 0xd0000001` = `M_CMD_DONE(0)` + **`M_TX_FIFO_RD_ERR(28)`** + `M_TX_FIFO_WATERMARK(30)`，
同刻 `tx trans_len 0x4 / m_gp_length 0 / tx_fifo 0` ⇒ 序列器去读 FIFO 时读到空的。

三轮实验（都已上机）：

| 镜像 | 顺序 | 自环 | 249 B 段 |
|---|---|---|---|
| `boot-yr` | 灌 FIFO → TRANS_LEN → 起命令 | `fe 03 00 00` FAIL | `cancel TIMED OUT`、`m_cmd_ctrl 0x4` 残留 |
| `boot-ys` | TRANS_LEN → 灌 → 起命令 | `fe 03 00 00` FAIL | 同上 |
| `boot-yt` | **Linux 原序**（TRANS_LEN → 起 → 推） | **PASS** | 仍 `0xd0000001` |

⇒ **块在命令启动时会丢掉 FIFO 里已有的数据，预灌不是解法；顺序定案为 Linux 原序。**

### 5.3 待上机的最后一次实验：`boot-yw.img`

`f1477875236c541d6a72b3709021b0b893a7d0496e94ea01f665d90a38d73c89`（54,841,344 B）

1. **`TRANS_LEN` 从字节数改为字数** `(n+3)/4`（bit21 保留字节数做 A/B）。
   假设：这颗块要的是 word count，写 249 而只给 63 个 word ⇒ 序列器继续要数据、读空 ⇒ RD_ERR。
2. `bt_rx_restart()` 恢复有界等待（50 ms），拆出**非阻塞版 `bt_rx_restart_soft()`** 给 TX 推入路径
   —— `bt_rx_pump()` 原来从推入循环里调阻塞版，每次 200 ms，而 16 word FIFO 5.5 ms 就排空。
3. `bt_se_putword()` 回到"只读占用、满了才等"（`boot-yu` 加的"先等水位锁存"会让序列器空读，
   实测把自环打成 `0c 97 6a f1`）。

## 六、两个「我以为读得到」的坑

### 6.1 `cat /sys/kernel/debug/regmap/100000.clock-controller/registers`

`ls -l` 是 **0 字节**，看着像空文件，实际是伪文件：读它会把整个 GCC 走一遍
（`range 0-1f41f0`，128K 寄存器），其中有带读副作用的，读到即断电并产生不可恢复
总线错误 → 整机复位。

### 6.2 `bt_se_census()` 扫 192 个偏移

把只验证过"读已知安全偏移"的探针扩展成 0x40 步长全网格，基址含 **`0x000`**
（`geni-se.h` 最低是 `GENI_GENERAL_CFG 0x010`）与 `0xe00..0xe3c` 的 vendor 私有尾，
并且在每段下载时都调用。**11-12 手机从 USB 完全消失，这是第一嫌疑。** 已彻底删除。

**唯一安全的取证路径**：
`/sys/kernel/debug/clk/clk_summary`、`/sys/kernel/debug/clk/<clk>/clk_print_regs`
（单时钟导出）、`/sys/kernel/debug/pinctrl/f000000.pinctrl/pinmux-{functions,pins}`。
`debugfs` 默认没挂载，先 `mount -t debugfs none /sys/kernel/debug`。

另注：`/sys/class/regulator/*` 有 106 个调节器，但 `bt*/wcn*/pcie*/wlan*/rf*` **一个都匹配不到**；
BT 那几路只在 `regulator_summary` 里以 `pmh0110_f_s7` / `pmh0104_s2` 这种 PMIC 名出现。

## 七、留给下一个人的接力点

1. 引导 `boot-yw.img`：`m command did not retire` 是否归零、`m_gp_length` 是否开始计数、
   自环是否仍是 `a5 5a 3c c3`。
2. 若仍 `0xd0000001`，做帧长扫描（16 / 32 / 64 / 128 B）定位 RD_ERR 首次出现的字节位。
3. cancel 路径改用 `M_GENI_CMD_ABORT`(BIT1) + 等 `M_CMD_ABORT_EN`(BIT5)，
   替代 `M_GENI_CMD_CANCEL`(BIT2)。
4. ROM 静默的备选：`btpower.ko` 的 `bt_resetb` 脉冲 —— 但 overlay 里
   `qcom,bt-reset-gpio` 与 `qcom,bt-en-gpio` **都指同一个 pmh0104 GPIO5**，没有独立 resetb。
5. `bluetooth_a`（FAT12）间歇 ENOENT：同镜像 YB/YG/YI 三次读到 320,728 B，YJ 那次四个文件
   全 `ENOENT`。不是路径错（`image/` 双前缀早修）。
